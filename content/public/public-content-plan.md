# Public Content Plan

The first version of Lumi Wiki should feel small, polished, and intentional. The goal is not volume. The goal is trust.

## Near-term collections

### Start Here

Orientation pages for what Lumi Wiki is, how to browse it, and what the privacy boundary means.

### AI Product & Workflow Notes

Public-safe explainers about AI product ownership, workflow design, evaluation habits, and useful patterns from hands-on building.

### Business Analysis & Consulting Notes

Reusable frameworks for discovery, stakeholder questions, requirements shaping, and solution thinking — written without client-specific details.

### Shadow Geeks Systems

Public documentation for family-safe systems, agent roles, publishing workflows, and lessons learned from building tools together.

## Quality bar

Every public note should have:

- one clear purpose
- a short description
- stable tags
- no private references
- enough context for a stranger to understand it
- practical value beyond being an archive

## V1 priority

Build the wiki as a product-like reading surface first. Once the shell feels reliable, add more approved notes gradually.
